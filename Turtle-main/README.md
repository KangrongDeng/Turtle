## ChatGPT项目书

### 1. 项目概述

项目名称（暂定）：Tidebound — 小海龟回家记（或 Find My Mother, Turtle!）

形式：2D 叙事探索（SpriteKit 场景）+ NPC 对话（Foundation Models 端侧生成）+ 线索收集（轻量解谜）

主题：海洋动物与濒危物种科普 + 海洋保护倡导（social impact）

一句话电梯陈述：

玩家扮演刚孵化的小海龟，从沙滩进入海洋，通过与不同海洋动物的“AI 对话”获得线索与知识卡片，最终找到海龟妈妈并完成“回到海流”的旅程。


### 2. 目标与评审导向

#### 2.1 作品目标

    1. 创新点：在离线环境下，用 Foundation Models 让每次对话“微变化”，同时保持安全与可控（可评审、可复现）。
     ￼
    2. 社会影响：以濒危物种为核心 NPC，让“了解—共情—行动建议”自然融入玩法。
    
    3. 完成度：3–5 分钟内能体验完整闭环（出生→入海→3–5 位 NPC→线索拼合→找到妈妈→结尾行动号召）。

#### 2.2 SSC 硬性约束

    -   离线：不依赖网络；所有资源本地包含。 ￼
    
    -   体积：ZIP ≤ 25MB（所以素材要“省”，尽量程序化/重复利用）。 ￼
    
    -   格式：App Playground（.swiftpm）+ ZIP。 ￼


### 3. 核心体验设计

#### 3.1 玩法循环（Gameplay Loop）

    1.    探索：在当前场景游动（左/右/上/下）→发现动物 NPC
    
    2.    对话：与 NPC 触发对话面板（Foundation Models 生成对话）
    
    3.    获得：得到“线索片段 + 物种卡片（濒危等级/威胁/保护建议）”
    
    4.    推进：集齐线索→解锁通往下一个区域的海流/通道
    
    5.    终局：找到妈妈→合流回迁徙路线→“你能做什么”小结

#### 3.2 场景分章（建议 4 幕，评审节奏清晰）

    -   序章：沙滩（教学：移动/互动）
    
    -   第一幕：浅海海草床（第一位 NPC：海马/海龟同伴）
    
    -   第二幕：珊瑚礁边缘（2 位 NPC：鹦嘴鱼、蝠鲼等）
    
    -   第三幕：外海蓝色海域（濒危主角 NPC：鲸鲨/海豚/海牛/锤头鲨等）
    
    -   终章：海流汇合处（母龟出现 + 结尾）

物种选择建议：优先挑 “大众有感知 + 视觉好做 + 信息好讲” 的濒危动物；数量控制在 3–5 个，比堆很多更稳。


### 4. AI 对话设计（Foundation Models）

#### 4.1 使用原则（保证“可控”和“可评审”）

Foundation Models 是端侧模型接口，偏“任务型文本能力”，不建议让它自由发挥成百科聊天。 ￼
因此对话建议采用：

    -   结构化提示词（System/Instruction）：限定角色、语气、长度、输出格式
    
    -   受控变量：只让模型在“表达方式/例子/类比”上变化，线索内容保持确定
    
    -   硬约束输出：让模型返回 JSON（或可解析的 key-value），便于 UI 渲染与调试

#### 4.2 对话输出格式（建议）

让模型输出类似：

    -   npcLine: NPC 的一句话回复（≤ 2 句）
    
    -   hint: 给玩家的线索（固定候选集之一）
    
    -   factCard: 物种知识卡（威胁/保护建议/一句数据）
    
    -   tone: 情绪标签（calm / urgent / playful）

这样你可以：

    -   UI 统一渲染
    
    -   线索始终可拼合
    
    -   评审每次体验不会跑飞

#### 4.3 安全与一致性策略

    -   黑名单/拒答：提示词要求避免敏感/不相关内容；不确定就回到“海洋保护主题”
    
    -   回退机制：生成失败或解析失败 → 使用本地预写台词（保证离线稳定）
    
    -   缓存：同一 NPC 第一次生成后缓存结果（减少重复调用、提升流畅）

（你可以在项目书里明确写：为满足离线与稳定性，AI 仅在“表达”上有随机性，关键线索与科普事实来自本地数据表。）



### 5. 系统架构（建议分层，方便写得清楚）

#### 5.1 模块划分
    1.    Game（SpriteKit）
    
        -   Scene：沙滩/浅海/珊瑚/外海/终章
        
        -   PlayerController：移动、碰撞、交互
        
        -   NPCEntity：位置、触发半径、状态机（未遇见/对话中/已完成）
        
    2.    Dialogue（Foundation Models）
    
        -   DialogueManager：构建提示词、请求、解析、缓存、失败回退
        
        -   PromptTemplates：每个 NPC 一个模板 + 公共规则
        
    3.    Content（本地数据）
    
        -   SpeciesDB：JSON（物种名、濒危等级、威胁、保护建议、固定线索池）
        
        -   HintGraph：线索拼图（收集 A+B+C → 解锁下一幕）
        
    4.    UI（SwiftUI Overlay 或 SpriteKit 内 UI）
    
        -   DialogueView：对话框、选项按钮（可做 2–3 个选项增加互动感）
        
        -   CardView：物种卡片（可收藏翻阅）
        
        -   ProgressView：线索进度条/地图

#### 5.2 状态机（关键）

        -   游戏总状态：tutorial → act1 → act2 → act3 → finale
        
        -   NPC 状态：idle → engaged → completed
        
        -   对话状态：generating → showing → reward

状态机写清楚，开发会非常顺。


### 6. 资源与美术策略（25MB 约束下的方案）

        -   尽量矢量化/程序化：背景用渐变、噪声、简单形状叠加
        
        -   精灵图复用：同一套鱼类骨架换色/换贴图
        
        -   音效轻量：短 WAV/CAF，循环 BGM 1 条即可（或者不用 BGM，用环境音）
        
        -   文字与卡片为主：把“信息量”放在卡片与对话里，节省美术体积

明确写在项目书里：为了满足 ZIP ≤ 25MB 与离线评审要求，采用轻量资源策略。 ￼

提交窗口从 2/6 开始，建议你在 2/1 前做到“可玩可通关”，之后只做 polish。

    -   接入 Foundation Models（DialogueManager + 模板 + 解析 + 缓存） ￼

    -   失败回退（本地台词）

Milestone C（1/28–2/1）：完整闭环可通关

    -   4 幕场景串起来（可简化成 2–3 个场景也行）

    -   结尾母龟与行动号召页面（可附“我能做什么：减少塑料/支持保护组织/科普分享”等）

Milestone D（2/2–2/5）：打磨与压缩

    -   性能：帧率、内存（减少粒子、贴图尺寸）

    -   体积：资源压缩，确保 ZIP ≤ 25MB  ￼
    
    -   录一段 30–60 秒“评审路径”自测：从开始到结尾不绕路

Milestone E（2/6–2/28）：提交窗口内迭代

    -   只做低风险优化：文案、UI、Bugfix、资源压缩
    
    -   避免大改架构



### 8. 风险清单与应对

    1.    AI 输出不稳定 / 跑题
    
        -   结构化输出 + 线索固定候选 + 解析失败回退
        
    2.    离线与权限问题
    
        -   不用网络；所有数据本地；首次启动就能玩  ￼
        
    3.    包体过大
    
        -   资源复用、贴图降尺寸、减少音频、优先程序化背景
        
    4.    评审时间有限
    
        -   3–5 分钟内闭环；主线路径明显；少做支线
